📖 Lectura teórica

1. Objetivo del diagnóstico

Diagnosticar consiste en reunir evidencias, formular hipótesis y comprobarlas con pruebas apropiadas. Un aviso no es una avería confirmada. Se anotan síntomas, condiciones de aparición, fecha y cambios recientes antes de intervenir.

2. Secuencia de trabajo

Primero se reproduce el síntoma de manera segura. Después se consulta el estado del equipo, se seleccionan pruebas no destructivas, se registran resultados y se contrastan. Se cambia una sola variable cada vez y se documenta si el problema persiste.

3. Memoria RAM

Los errores de RAM pueden producir bloqueos, cierres inesperados o fallos de arranque, pero esos síntomas también tienen otras causas. El Diagnóstico de memoria de Windows y MemTest86 son ejemplos de herramientas de prueba. Un error repetido merece investigación; una prueba sin errores no garantiza que la RAM esté perfecta.

4. Pruebas de memoria

Las pruebas deben ejecutarse con autorización, preferiblemente fuera de la sesión habitual y durante el tiempo suficiente. Si aparecen errores, se registra el número de prueba y la configuración; después se comprueban módulos, ranuras y ajustes de memoria siguiendo el protocolo del centro. Nunca se extrae RAM con el equipo encendido.

5. Estado del almacenamiento

S.M.A.R.T. es un conjunto de datos de autovigilancia que pueden ofrecer las unidades compatibles. Permite observar indicadores y avisos de salud, pero no predice todas las averías. Un estado «correcto» no excluye fallos y una alerta exige contrastar información y proteger los datos.

6. Herramientas de almacenamiento

En Windows se puede consultar el estado con herramientas del fabricante o utilidades del sistema; en Linux, smartctl cuando está disponible y autorizado. Las pruebas extensas pueden consumir tiempo. No se ejecutan operaciones destructivas ni reparaciones sobre datos importantes sin copia y permiso.

7. Temperaturas

La CPU, GPU y las unidades pueden tener sensores térmicos. Se registran temperatura en reposo y bajo una tarea comparable, junto con temperatura ambiente, ventiladores y frecuencia. Los límites admisibles dependen del modelo y las especificaciones del fabricante.

8. Refrigeración y rendimiento

Un filtro obstruido, ventilador detenido o disipador mal instalado puede elevar temperaturas. El thermal throttling reduce rendimiento para controlar el calor. Una temperatura alta aislada no demuestra cuál es la causa; hay que comparar con evidencias adicionales.

9. Registros del sistema

El Visor de eventos de Windows permite examinar eventos de sistema y aplicaciones. En Linux, journalctl permite consultar registros si el sistema lo utiliza y el usuario tiene permisos. Un evento debe interpretarse junto con la hora del incidente y otros datos: correlación temporal no demuestra causalidad.

10. Precauciones

Antes de abrir un equipo se apaga y desconecta de la red, respetando las normas ESD. No se abre la fuente de alimentación. Antes de pruebas que puedan afectar a datos se realiza copia de seguridad y se solicita autorización. Se preserva la información del usuario.

11. Caso guiado

Un SSD muestra una advertencia de salud. El alumno anota el mensaje exacto, modelo y fecha, comprueba que existe copia de seguridad y consulta los indicadores disponibles con una herramienta autorizada. El aviso orienta la investigación, pero por sí solo no determina la causa definitiva.

12. Informe técnico

El informe incluye identificación del equipo, síntoma, pruebas realizadas, condiciones, resultados con unidades, capturas o registros, hipótesis y siguiente acción recomendada. Debe distinguir hechos observados de conclusiones provisionales y explicar qué pruebas faltan.

1. Un aviso de almacenamiento confirma por sí solo una avería concreta.
2. El diagnóstico debe basarse en evidencias contrastables.
3. Es útil anotar cuándo apareció un síntoma.
4. Cambiar varias piezas a la vez facilita aislar la causa.
5. Los errores de RAM pueden provocar bloqueos.
6. Una prueba de RAM sin errores garantiza que nunca fallará.
7. MemTest86 es una herramienta de prueba de memoria.
8. Se puede retirar un módulo RAM con el ordenador encendido.
9. S.M.A.R.T. puede aportar indicadores sobre el estado de una unidad.
10. S.M.A.R.T. predice todas las averías de disco.
11. Una alerta de almacenamiento aconseja revisar la copia de seguridad.
12. Una operación destructiva debe hacerse sin autorización.
13. smartctl puede consultar información de unidades compatibles.
14. Las temperaturas admisibles son iguales para todas las CPU.
15. Conviene comparar temperaturas bajo la misma carga.
16. Un ventilador detenido puede contribuir al sobrecalentamiento.
17. Thermal throttling puede reducir el rendimiento.
18. Una temperatura elevada identifica por sí sola el componente averiado.
19. El Visor de eventos registra información útil del sistema.
20. journalctl puede consultar registros en sistemas Linux compatibles.
21. Un evento cercano en el tiempo demuestra siempre la causa del fallo.
22. El registro de la hora del problema ayuda al análisis.
23. Se debe abrir la fuente para comprobar sus condensadores.
24. El informe debe separar observaciones de hipótesis.
25. Una prueba debe realizarse conforme a las autorizaciones del centro.
